# Feature Specification: lab: 해결해야 다음 문제가 열리는 오늘의 문제

**Feature Branch**: `004-lab-solve-gated-daily`

**Created**: 2026-10-29

**Status**: Draft

**Input**: User description: "lab: 매일 문제 알림을 \"이전 문제를 해결해야 다음 문제가 올라오는\" 방식으로 변경한다.
- 오늘의 문제는 Incoming Webhook 대신 Slack 봇 토큰(chat.postMessage)으로 게시하고, 게시한 메시지의 채널·메시지 ID와 시나리오 이름을 상태 파일에 저장한다
- 매일 오전 9시 실행 시 직전 문제 메시지에 사용자(SLACK_USER_ID)가 ✅ 반응을 달았는지 확인한다
  - ✅가 있으면: 해결로 기록하고 다음 문제를 게시한다
  - ✅가 없으면: 새 문제를 올리지 않고, 직전 문제 스레드에 \"아직 해결 전\" 리마인드를 남긴다 (리마인드는 같은 문제에 하루 한 번만, 3일 이상 밀리면 힌트 1단계를 함께 안내한다)
- /lab-check로 해결이 확인되면 직전 문제 메시지에 자동으로 ✅를 달아 준다 (직접 달아도 인정)
- 사용자가 ⏭️ 반응을 달면 해결하지 않고 건너뛴 것으로 기록하고 다음 문제로 넘어간다 (건너뛴 문제는 약점으로 기록해 나중에 다시 추천한다)
- 주간 요약은 그대로 일요일에 보내고, 해결·건너뜀·미해결 일수를 포함한다
- Slack 값은 SLACK_BOT_TOKEN, SLACK_LAB_CHANNEL_ID, SLACK_USER_ID 환경변수(GitHub Secrets)로 받는다"

## 배경

지금(002)은 매일 아침 21일 커리큘럼의 다음 날 차 문제를 웹훅으로 올리고, 풀지 못한 문제가 3개 이상
쌓이면 밀린 문제(catchup)를 다시 올린다. 문제가 풀었는지와 상관없이 매일 올라오므로, 바쁜 날이 이어지면
밀린 목록만 길어지고 학습자는 어떤 문제부터 손대야 할지 흐려진다.

이 기능은 게시 흐름을 "한 번에 한 문제"로 바꾼다. 채널에는 항상 지금 풀어야 할 문제 하나만 열려 있고,
그 문제에 ✅가 달려야 다음 문제가 올라온다. 건너뛰기는 없다. 학습자의 상태 표시는 Slack 메시지의
반응 하나로 끝나고, 실습 명령으로 해결을 확인하면 반응도 자동으로 달린다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 풀어야 다음 문제가 올라온다 (Priority: P1)

학습자는 아침 9시쯤 lab 채널에서 오늘의 문제를 받는다. 다 풀면 그 메시지에 ✅를 단다. 다음 날 아침 봇이
✅를 확인하고 다음 문제를 올린다. 아직 못 풀었으면 새 문제 대신 그 문제의 스레드에 "아직 해결 전"이라는
리마인드가 달린다.

**Why this priority**: 이 기능의 핵심이다. 게시 방식(봇 토큰), 메시지 위치 기록, 반응 확인, 다음 문제
게시/리마인드가 모두 이 흐름 하나에 들어 있고, 이것만 있어도 "한 번에 한 문제" 학습이 성립한다.

**Independent Test**: Slack을 모킹한 상태에서 (1) 첫 게시 → 게시 기록에 채널·메시지 ID·항목 이름 저장,
(2) 다음 날 학습자의 ✅가 있음 → 해결 기록 + 다음 문제 게시, (3) ✅가 없음 → 새 게시 없이 스레드 리마인드
1건, 세 경우를 날짜를 바꿔 가며 실행해 확인한다.

**Acceptance Scenarios**:

1. **Given** 열린 문제가 없는 상태(첫 실행 또는 직전 문제가 끝남), **When** 아침 실행, **Then** 커리큘럼 순서상
   다음 문제를 lab 채널에 게시하고, 게시한 메시지의 채널 ID·메시지 ID·항목 ID·게시 날짜를 게시 기록에 남긴다.
2. **Given** 직전 문제 메시지에 학습자가 ✅를 단 상태, **When** 아침 실행, **Then** 그 문제를 "해결"로 기록하고
   다음 문제를 게시한다.
3. **Given** 직전 문제 메시지에 ✅가 없는 상태, **When** 아침 실행, **Then** 새 문제를 게시하지 않고 직전 문제
   메시지의 스레드에 "아직 해결 전" 리마인드를 1건 남긴다.
4. **Given** 같은 날 이미 리마인드를 남긴 상태, **When** 그날 다시 실행(수동 재실행 등), **Then** 리마인드를 또 남기지
   않는다.
5. **Given** 직전 문제가 게시된 지 3일 이상 지나도 해결되지 않은 상태, **When** 아침 실행, **Then** 리마인드에
   그 문제의 힌트 1단계를 함께 담는다.
6. **Given** 학습자가 아닌 다른 사람만 ✅를 단 상태, **When** 아침 실행, **Then** 해결로 보지 않고 리마인드를 남긴다.

### User Story 2 - 실습에서 해결하면 ✅가 자동으로 달린다 (Priority: P2)

학습자가 로컬에서 `/lab-check`로 문제를 검증해 통과하면, Slack의 그 문제 메시지에 ✅가 자동으로 달린다.
학습자가 Slack에 들어가 직접 반응을 달 필요가 없다. 직접 달아도 똑같이 인정된다.

**Why this priority**: P1만으로도 학습자가 직접 ✅를 달면 흐름이 돈다. 자동 반응은 실습과 Slack 사이의
수작업을 없애 주는 편의 기능이다.

**Independent Test**: Slack을 모킹한 상태에서 열린 문제가 기록된 게시 기록을 두고 검증 통과를 흉내 내어,
해당 메시지에 ✅ 반응 요청이 1번 가는지, 검증이 실패하면 가지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 오늘의 문제가 열려 있고 학습자가 그 문제를 풀고 있는 상태, **When** `/lab-check`가 해결을 확인,
   **Then** 그 문제 메시지에 ✅ 반응이 달리고, 학습자에게 "Slack에 ✅를 달았어요"라고 알린다.
2. **Given** 오늘의 문제에 항목이 둘(본 문제 + 두 번째 항목) 있는 상태, **When** 그중 하나만 해결, **Then** 아직
   ✅를 달지 않고, 둘 다 해결된 시점에 단다.
3. **Given** 열린 문제와 다른 항목을 검증한 상태(예: 지난 문제 다시 풀기), **When** 해결 확인, **Then** 열린 문제
   메시지에는 반응을 달지 않는다.
4. **Given** 이미 ✅가 달려 있는 상태, **When** 다시 해결 확인, **Then** 오류 없이 넘어간다.
5. **Given** Slack 연결이 실패한 상태, **When** 해결 확인, **Then** 검증 결과와 진행 기록은 그대로 남고,
   "✅ 자동 반응을 달지 못했어요. Slack에서 직접 달아 주세요"라고 안내한다.
6. **Given** 봇이 단 ✅만 있는 상태, **When** 아침 실행, **Then** 학습자가 단 것과 똑같이 해결로 인정한다.

---

### User Story 3 - 일요일 요약에서 한 주의 진행을 본다 (Priority: P3)

일요일 아침 실행에서 지금처럼 주간 요약이 올라오고, 이번 주에 해결한 문제 수와 문제가
풀리지 않아 새 문제가 올라오지 않은 날 수가 함께 나온다.

**Why this priority**: 주간 요약 자체는 이미 있다. 새 흐름의 지표만 더하는 일이라 P1–P2가 동작한 뒤에 의미가 있다.

**Independent Test**: 한 주 치 게시 기록(해결 2, 리마인드만 있던 날 3)을 준비해 일요일 실행 시
요약에 두 숫자가 그대로 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이번 주(월~일, KST)에 해결 2건, 리마인드만 남긴 날 3일이 있는 상태, **When** 일요일 실행,
   **Then** 주간 요약에 "해결 2 · 미해결로 멈춘 날 3일"이 나온다.
2. **Given** 일요일에 직전 문제가 아직 미해결, **When** 일요일 실행, **Then** 리마인드와 주간 요약이 모두 나간다.

---

### Edge Cases

- **기능 도입 직후 첫 실행**: 기존 게시 기록에는 메시지 위치가 없다. 위치 없는 직전 게시는 "끝난 문제"로 보고 다음
  문제를 게시한다(기존 해결 여부 판단은 진행 기록 그대로 사용).
- **직전 문제 메시지가 삭제됐거나 찾을 수 없음**: 해결 여부를 알 수 없으므로 같은 문제를 새 메시지로 다시 게시하고,
  새 메시지 위치로 기록을 바꾼 뒤 테스트 채널에 경고를 보낸다. 다음 문제로 넘어가지 않는다.
- **⏭️ 등 다른 반응**: ✅ 외의 반응은 판정에 쓰지 않는다. 문제를 넘기려면 ✅를 달아야 한다.
- **포기(`/lab-giveup`)**: 포기는 진행 기록에만 남고 문제를 넘기지 않는다. 그 문제는 ✅가 달릴 때까지 열려 있고 리마인드가 계속된다.
- **반응을 달았다가 지움**: 아침 실행 시점에 남아 있는 반응만 본다.
- **반응 없이 진행 기록만 있음**: 진행 기록에 열린 문제의 해결이 있어도 메시지에 ✅가 없으면 미해결로 보고 새 문제를
  주지 않는다. 판정 기준은 오직 메시지의 ✅다.
- **미해결이 아주 길어짐**: 리마인드는 하루 한 번씩 계속되고, 3일 차부터는 매번 힌트 1단계를 함께 담는다. 2단계 이상의
  힌트는 자동으로 보내지 않는다.
- **힌트가 없는 항목(개념 미션 등)**: 3일 이상 밀려도 힌트 없이 리마인드만 남긴다.
- **Slack 호출 실패(게시·반응 조회·리마인드)**: 재시도 후에도 실패하면 기록을 바꾸지 않고(해결 기록 포함)
  테스트 채널에 실패를 알린다. 다음 날 같은 판단을 다시 한다.
- **필수 Slack 값 누락**: `SLACK_BOT_TOKEN`, `SLACK_LAB_CHANNEL_ID`, `SLACK_USER_ID` 중 하나라도 없으면 아무것도
  게시하지 않고 빠진 이름만 알린다(값은 출력하지 않는다).
- **봇이 채널에 없거나 권한 부족**: 게시 실패로 처리하고, 원인(채널 미초대·권한 부족)을 알 수 있는 오류 요약을 테스트 채널에 보낸다.
- **같은 날 여러 번 실행**: 게시·해결 기록·리마인드 모두 하루 한 번만 일어난다.
- **로컬 게시 기록이 오래됨**: `/lab-check`를 실행한 로컬 레포의 게시 기록이 최신이 아니면 열린 문제를 잘못 알 수 있다.
  로컬 기록이 가리키는 메시지가 지금 검증한 항목이 아니면 반응을 달지 않고, 최신 기록을 받아 오라고 안내한다.
- **테스트 채널 대상 실행/미리 보기**: 게시 기록과 학습 상태를 바꾸지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**게시와 기록**

- **FR-001**: 오늘의 문제와 주간 요약은 MUST 봇 계정으로 lab 채널에 게시한다. lab 채널 게시에 웹훅을 더 이상 쓰지 않는다.
- **FR-002**: 오늘의 문제를 게시하면 MUST 게시 기록에 채널 ID, 메시지 ID, 항목 ID(본 문제와 두 번째 항목), 게시 날짜를 남긴다.
- **FR-003**: 시스템은 MUST 한 번에 열린 문제를 최대 하나만 둔다. 열린 문제란 게시됐지만 아직 해결이 기록되지 않은 문제다.
- **FR-004**: 다음 문제는 MUST 기존 21일 커리큘럼 → 심화 → 복습 순서를 따른다. 다만 커리큘럼 "일 차"는 날짜가 아니라
  열린 문제가 해결될 때마다 하나씩 나아간다.
- **FR-005**: 밀린 문제가 3개 이상이면 다시 올리던 기존 규칙(catchup)은 MUST 없앤다. 한 번에 한 문제만 열리므로 밀린 목록이 생기지 않는다.

**아침 판정**

- **FR-006**: 아침 실행은 MUST 열린 문제 메시지의 반응을 조회해 판정한다:
  ✅(학습자 또는 봇) 있음 → 해결 / 없음 → 미해결. ✅ 외의 반응(⏭️ 등)은 판정에 쓰지 않는다.
- **FR-007**: 학습자와 봇이 아닌 사람이 단 반응은 MUST 무시한다.
- **FR-008**: 해결이면 MUST 그 결과와 판정 시각을 게시 기록에 남기고, 같은 실행에서 다음 문제를 게시한다.
- **FR-009**: 미해결이면 MUST 새 문제를 게시하지 않고, 열린 문제 메시지의 스레드에 "아직 해결 전" 리마인드를 남기며 그 날짜를 기록한다.
- **FR-010**: 같은 문제에 대한 리마인드는 MUST 하루(KST)에 최대 1건이다.
- **FR-011**: 열린 문제가 게시된 날로부터 3일 이상 지났으면 리마인드는 MUST 그 문제의 힌트 1단계 내용을 함께 담는다. 힌트가 없는 항목은 리마인드만 보낸다.
- **FR-012**: 판정은 MUST 메시지의 반응만으로 한다. 진행 기록에 해결이 있어도 ✅가 없으면 미해결로 보고 새 문제를 게시하지 않는다.

**실습 명령과 자동 반응**

- **FR-013**: `/lab-check`가 열린 문제의 모든 항목이 해결됐음을 확인하면 MUST 그 문제 메시지에 봇 계정으로 ✅를 단다.
- **FR-014**: `/lab-giveup`으로 열린 문제를 포기해도 MUST 반응을 달지 않는다. 그 문제는 계속 열려 있다.
- **FR-015**: 자동 반응이 실패해도 MUST 검증 결과와 진행 기록은 그대로 유지하고, 학습자에게 직접 반응을 달라고 안내한다.
- **FR-016**: 이미 같은 반응이 있으면 MUST 오류 없이 넘어간다.

**건너뛰기 없음**

- **FR-017**: 시스템은 MUST 건너뛰기 기능을 제공하지 않는다. 열린 문제는 ✅로만 끝난다.
- **FR-018**: 복습 추천 순서와 주간 약점 분야 계산은 MUST 지금(002) 규칙을 그대로 쓴다.

**주간 요약**

- **FR-019**: 일요일 아침 실행은 MUST 지금처럼 주간 요약을 게시하고, 이번 주의 해결 수와 미해결로 새 문제가 올라오지
  않은 날 수를 포함한다.
- **FR-020**: 주간 요약에서 "밀린 문제 수" 항목은 MUST "지금 열린 문제(게시 후 경과 일수)"로 바꾼다.

**설정·안전·실패 처리**

- **FR-021**: Slack 값은 MUST 환경변수 `SLACK_BOT_TOKEN`, `SLACK_LAB_CHANNEL_ID`, `SLACK_USER_ID`로만 받는다.
  GitHub Actions에서는 같은 이름의 Secrets로 넘긴다. 로컬의 `/lab-check` 자동 반응도 같은 이름을 쓴다.
- **FR-022**: 필수 값이 없으면 MUST 아무것도 게시·기록하지 않고 빠진 이름만 출력한다. 값 자체는 출력·로그에 남기지 않는다.
- **FR-023**: 모든 Slack 호출은 MUST 횟수 제한이 있는 지수 백오프 재시도를 적용하고, 최종 실패는 대상·시도 횟수·오류 요약으로 로깅한다.
- **FR-024**: 게시, 반응 조회, 리마인드 중 하나라도 최종 실패하면 MUST 그 실행에서 게시 기록을 바꾸지 않고 테스트 채널에 알린다.
- **FR-025**: 테스트 채널 대상 실행과 미리 보기 실행은 MUST 게시 기록과 학습 상태를 바꾸지 않는다.
- **FR-026**: 실패 알림 경로(테스트 채널 웹훅)는 MUST 지금처럼 유지한다.

### Key Entities *(include if feature involves data)*

- **게시된 문제(게시 기록의 항목)**: 날짜, 일 차/심화/복습 구분, 본 문제 ID와 두 번째 항목 ID, 메시지 위치(채널 ID·메시지 ID),
  결과(열림/해결)와 판정 시각, 리마인드를 남긴 날짜 목록.
- **열린 문제**: 결과가 "열림"인 가장 최근 게시 문제. 항상 0개 또는 1개.
- **리마인드**: 열린 문제 스레드에 남긴 안내. 날짜, 힌트 1단계 포함 여부.
- **반응 판정**: 아침 실행이 조회한 ✅(누가 달았는지)와 그로부터 나온 결론.
- **주간 요약**: 기존 항목 + 해결 수, 미해결로 멈춘 날 수, 지금 열린 문제.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 어느 시점이든 lab 채널에 열린 문제는 최대 1개다(게시 기록으로 검증).
- **SC-002**: ✅를 단 다음 날 아침 실행에서 100% 다음 문제가 올라온다(Slack 장애로 실패한 날 제외, 그 경우 테스트 채널 알림 100%).
- **SC-003**: ✅가 없으면 그날 새 문제는 0건이고, 같은 문제에 대한 리마인드는 하루 1건을 넘지 않는다.
- **SC-004**: `/lab-check`로 해결을 확인한 경우 학습자가 Slack을 열지 않고도 다음 날 다음 문제를 받는다.
- **SC-005**: 미해결 3일 차부터의 리마인드 100%에 힌트 1단계가 담긴다(힌트가 있는 항목 기준).
- **SC-006**: 일요일 요약의 해결 수와 멈춘 날 수가 그 주 게시 기록과 정확히 일치한다.
- **SC-007**: 비밀값이 출력·로그·커밋에 한 번도 나타나지 않는다.

## Assumptions

- 학습자는 1명이고 `SLACK_USER_ID`가 그 사람이다. 다른 사람의 반응은 판정에 쓰지 않는다.
- 봇 계정은 lab 채널에 초대돼 있고, 메시지 게시·반응 조회·반응 추가·스레드 답글에 필요한 권한을 가진다.
- 봇이 단 ✅는 `/lab-check`가 단 것으로 보고 학습자 것과 똑같이 인정한다.
- 처음 요청에 있던 ⏭️ 건너뛰기는 2026-10-29 대화에서 빼기로 했다. ✅가 없으면 무조건 새 문제를 주지 않는다.
  못 푸는 문제는 리마인드의 힌트 1단계와 `/lab-hint`로 풀어서 넘어간다.
- 리마인드에 담은 힌트 1단계는 학습자가 힌트를 연 것(힌트 사용 횟수)으로 세지 않는다. 학습자가 직접 `/lab-hint`로 열 때만 센다.
- "3일 이상 밀림"은 게시 날짜(KST)로부터 3일 이상 지난 날의 아침 실행을 뜻한다(예: 월요일 게시 → 목요일 리마인드부터 힌트 포함).
- 아침 실행 시각(KST 9시 무렵), 일요일 주간 요약, 실패 알림용 테스트 채널 웹훅은 지금 그대로 둔다.
- 테스트 채널 대상 실행은 미리 보기 용도로 남기며, 그때는 반응 판정 없이 "다음에 올라갈 문제"를 보여 준다.
- 게시 기록은 지금처럼 GitHub Actions가 커밋하고, 로컬 `/lab-check`는 로컬 레포의 게시 기록으로 열린 문제를 찾는다.
- 기존 게시 기록·진행 기록 형식은 하위 호환되게 확장한다(기존 항목은 메시지 위치 없이 "끝난 문제"로 읽힌다).
